# Go Daily — Architecture

This document describes how Go Daily is built and the conventions that keep it consistent. Update it whenever a structural decision changes.

## 1. System overview

```text
            ┌────────────────────┐        ┌─────────────────────┐
 Browser ──▶│  admin-web (Next)  │──────▶ │                     │
 (Arabic    │  BFF: server comps │ Bearer │   api (FastAPI)     │──▶ PostgreSQL 16
  RTL UI)   │  + server actions  │ token  │   services/models   │    (system of record)
            └────────────────────┘        │                     │
 Android  ─────────────────────────────▶  │                     │
 driver app        HTTPS + Bearer token   └─────────────────────┘
```

- **PostgreSQL** is the single system of record. All schema changes go through Alembic migrations.
- **api** owns all business rules and authorization. Clients are untrusted.
- **admin-web** is a backend-for-frontend (BFF). The browser never sees the API token, which lives in an `httpOnly` cookie. Server Components and Server Actions call the API from the Next.js server.
- **driver-android** (from Task 09) talks to the API directly with a bearer token stored in Android Keystore-backed storage.

## 2. Monorepo layout

```text
apps/api/
  app/
    core/        config, db, logging, errors, security, time helpers
    models/      SQLAlchemy ORM models (one module per domain area)
    schemas/     Pydantic request/response models
    services/    business logic (use cases); the only place that writes data
    api/         FastAPI routers (thin), dependencies (auth, RBAC)
    cli.py       operational commands (seed, bootstrap-admin)
  alembic/       migrations (hand-reviewed)
  tests/         pytest suite against real PostgreSQL
apps/admin-web/
  src/app/       App Router routes
  src/components UI components (presentational; no business rules)
  src/lib/       API client, session helpers, formatting
packages/config  tsconfig base and design tokens (theme.css and tokens.ts)
packages/shared  shared TS constants (roles, Arabic labels)
```

## 3. Backend conventions

### Layering

| Layer | Responsibility | Must not |
| --- | --- | --- |
| Route handler (`app/api/routes`) | Parse input, resolve current user, call a service, shape the response | contain business rules or queries beyond trivial lookups |
| Service (`app/services`) | Validate business rules, write data, write audit records, commit | depend on FastAPI request objects |
| Model (`app/models`) | Table structure and constraints | contain workflow logic |
| Schema (`app/schemas`) | Input validation (types, lengths, formats) and output shape | expose sensitive fields (password hashes, national IDs unless authorized) |

Services raise domain errors (`app/core/errors.py`): `NotFoundError`, `ConflictError`, `ValidationFailed`, `PermissionDenied` and so on. A global handler maps them to one envelope:

```json
{ "error": { "code": "conflict", "message": "رسالة بالعربية", "details": {} } }
```

`code` is stable and machine-readable. `message` is Arabic for direct display.

### Database

- **UUID primary keys**, generated in Python (`uuid4`) with `gen_random_uuid()` as the server default.
- **Timestamps** use `timestamptz`. Store UTC and show Africa/Cairo. Business-day boundaries ("today's shifts") are computed in the configured local timezone (`app/core/time.py`).
- **Money** uses `NUMERIC(14,2)` and **quantities** use `NUMERIC(14,3)`. Python uses `Decimal` and JSON carries strings. Binary floating point is never used for money.
- **Constraint naming convention** is defined in `app/models/base.py`, so migrations stay deterministic.
- **History is preserved.** Corrections create new records or audited updates. Historical facts are not hard-deleted (see Audit below).
- Migrations are autogenerated and then **reviewed by hand**. Never edit a migration that has already been applied in a shared environment.

### Transactions

A request gets one SQLAlchemy session (`get_db`). Services commit explicitly at the end of a use case. A use case that fails rolls back as a whole. Tests wrap each test in an outer transaction with savepoints, so service commits never leak between tests.

### Time

All server code uses `app.core.time.utcnow()`. Do not call `datetime.now()` without a timezone.

## 4. Frontend conventions

- **Arabic-first RTL.** `<html lang="ar" dir="rtl">`. Use logical Tailwind utilities (`ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`) instead of left/right. Numbers, plates and codes use the `ltr-nums` helper so they read left-to-right.
- **Latin digits** in numbers and money (`ar-EG-u-nu-latn`), matching receipts and inputs.
- **Design tokens** live in `packages/config/tokens/theme.css` (Tailwind v4 `@theme`) and are mirrored in `tokens.ts` for charts and maps:
  - dark forest green for primary and navigation
  - bright lime for actions, active state and GPS indicators
  - white surfaces on a light neutral background
  - charcoal text

  No purple/blue SaaS palette, glassmorphism or decorative animation.
- Business rules stay in the API. UI components only present data and collect input.
- Next.js 16 conventions:
  - `proxy.ts` replaces `middleware.ts`.
  - Request APIs are async.
  - `cacheComponents` is intentionally **off**: every admin screen is authenticated and dynamic.

## 5. Security model (summary)

Details are added as each phase lands. See Task 02 and Task 25.

- Authorization is enforced in the API on every endpoint. The frontend only hides navigation for convenience.
- Credentials and tokens are never logged. The JSON log formatter also redacts known sensitive keys.
- CORS allows only configured origins. Interactive API docs are disabled in production.
- Security headers on the admin web: `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`.

## 6. Observability

- JSON logs (one object per line) with a request ID. The ID is taken from `X-Request-ID` or generated, and echoed in the response.
- Liveness is `GET /health`. Readiness is `GET /ready`, which runs `SELECT 1` against the database and returns 503 on failure.

## 7. Local infrastructure

`compose.yaml` runs `postgres`, a one-shot `migrate` job, `api` and `admin-web`. Production images run as non-root users and include health checks. Dockerfiles accept an optional BuildKit secret `extra_ca` for building behind TLS-intercepting proxies. The secret is never stored in an image layer.

## 8. Decision log

| Date | Decision | Reason |
| --- | --- | --- |
| 2026-10-29 | Synchronous SQLAlchemy 2 with psycopg 3 | Simpler, well-tested code paths. FastAPI runs sync endpoints in a thread pool, which is ample for the expected fleet size. |
| 2026-10-29 | Real PostgreSQL in tests, schema built from migrations | The schema relies on PostgreSQL features, and the migration chain is verified on every run. |
| 2026-10-29 | Next.js `cacheComponents` disabled | The admin is fully authenticated and dynamic, so caching adds complexity without benefit. Revisit when Next.js makes it mandatory. |
| 2026-10-29 | Tailwind v4 tokens in a shared package | One source of truth for brand colours across web, charts and maps. |
