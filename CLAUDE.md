# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Go Daily: a fleet control and operations system for a transport company in Egypt (vehicles, drivers, shifts, GPS tracking during shifts, fixed and school routes, ride-hailing, fuel, expenses, revenue, driver cash and settlements, per-vehicle profitability). The UI is Arabic-first and RTL. Money is EGP. Timestamps are stored in UTC and shown in Africa/Cairo time.

Monorepo:
- `apps/api`: FastAPI, synchronous SQLAlchemy 2 + psycopg 3, Alembic, Python 3.12, managed with `uv`
- `apps/admin-web`: Next.js 16 App Router, React 19, Tailwind v4, vitest, pnpm workspace
- `apps/driver-android`: Kotlin and Compose. `core/` is pure JVM logic, `app/` is the Android shell.
- `packages/config` holds design tokens (`tokens/theme.css`, mirrored in `tokens.ts`). `packages/shared` holds shared TS constants such as roles and Arabic labels.

`docs/ARCHITECTURE.md` is the authoritative design doc. Each feature section names its service module and its tests. Read the relevant section before changing a domain area, and update it when a structural decision changes. Task and upgrade IDs (Task 20, U26, …) used in code and commits refer to `docs/GO_DAILY_CLAUDE_MASTER_TASKS.md` and `docs/GO_DAILY_UPGRADES_MASTER.md`. Progress is tracked in `docs/UPGRADE_STATUS.md`.

## Commands

The Makefile wraps everything (`make help`). It needs bash, so on Windows run the underlying commands directly.

```bash
make setup                 # uv sync (apps/api) + pnpm install; creates .env from .env.example
make dev                   # API :8000 (uvicorn --reload) + admin web :3000; needs PostgreSQL running
docker compose up -d postgres   # just the database
make migrate               # alembic upgrade head
make migration m="..."     # autogenerate, then REVIEW the file by hand
make seed                  # idempotent reference data only
make check                 # what CI runs: lint, typecheck, test, build
```

API (run from `apps/api`, or prefix with `uv --directory apps/api`):
```bash
uv run pytest                                   # all tests
uv run pytest tests/test_shifts.py              # one file
uv run pytest tests/test_shifts.py::test_name   # one test
uv run ruff check . && uv run ruff format --check .
uv run mypy app tests                           # strict
uv run python -m app.cli <cmd>                  # seed, bootstrap-admin, detect-exceptions, generate-notifications, prune-gps, prune-idempotency
```

Admin web:
```bash
pnpm --filter admin-web test                    # vitest run
pnpm --filter admin-web exec vitest run src/lib/format.test.ts
pnpm --filter admin-web lint                    # eslint --max-warnings=0
pnpm --filter admin-web format:check
pnpm --filter admin-web typecheck               # next typegen && tsc --noEmit
pnpm --filter admin-web build
```

Driver app (JDK 17): `cd apps/driver-android && ./gradlew -p core test` runs the pure logic tests and needs no Android SDK. `./gradlew :app:assembleDebug :app:lintDebug` needs the Android SDK and Google Maven.

### Tests use a real PostgreSQL

API tests connect to `TEST_DATABASE_URL`, which defaults to `postgresql+psycopg://godaily:godaily@localhost:5432/godaily_test`. **The session fixture drops and recreates the `public` schema** and builds it by running the Alembic migrations, so never point it at a database you care about. Each test runs in an outer transaction that is rolled back, and service commits become savepoint releases. Shared builders are in `tests/factories.py`. Pytest turns `DeprecationWarning` from `app.*` into errors.

CI also runs `alembic upgrade head`, then `downgrade base`, then `upgrade head`, then `alembic check`. Every migration therefore needs a working `downgrade()`, and the models must match the migrations exactly. Migrations are numbered sequentially (`alembic/versions/00NN_name.py`). Never edit a migration that has already been merged.

## Backend architecture

The API layers are strict:
- `app/api/routes/*` holds thin routers. They parse input, resolve the user, call a service and shape the response with `app/api/presenters.py` or `finance_presenters.py`.
- `app/services/*` holds all business rules. **It is the only layer that writes data**: it writes the audit records and commits explicitly at the end of a use case. Services do not depend on FastAPI request objects.
- `app/models/*` holds ORM tables and constraints. The constraint naming convention in `app/models/base.py` keeps autogenerated migrations deterministic.
- `app/schemas/*` holds Pydantic input and output models. They must never expose password hashes or national IDs without `drivers:read_sensitive`.
- Services raise domain errors from `app/core/errors.py` (`NotFoundError`, `ConflictError`, `ValidationFailed`, `PermissionDenied`, …). These map to `{"error": {"code", "message", "details"}}`. `code` is stable English and `message` is Arabic for display.

Cross-cutting rules that hold across many files:
- **Authorization lives in the API.** Permissions are strings (`vehicles:write`, `settlements:finalize`, …) mapped to roles in `app/core/permissions.py` and enforced with `require_permissions(...)`. The roles are `SUPER_ADMIN`, `ADMIN`, `OPERATIONS`, `ACCOUNTANT` and `DRIVER`. Drivers use only the `/api/v1/driver/*` endpoints, which are scoped to their own records. Hiding something in the web UI is never the security control.
- **Time:** use `app.core.time.utcnow()`. Never call a naive `datetime.now()`. Business-day boundaries use the local timezone helpers in `app/core/time.py`.
- **Money:** `Numeric(14,2)`, Python `Decimal`, decimal strings in JSON, ROUND_HALF_UP. Quantities use `Numeric(14,3)`. Never use floats for money.
- **Nothing historical is hard-deleted.**
  - Financial records go SUBMITTED → APPROVED or REJECTED.
  - An approved record is never edited. A correction voids it and creates a replacement linked by `corrects_id`.
  - Totals count APPROVED records only.
  - `audit_logs` is append-only: a DB trigger blocks UPDATE and DELETE. Audit rows are written in the same transaction as the change.
- **Concurrency:** write paths lock rows (`finance_common.fetch(lock=True)` → `SELECT … FOR UPDATE`). DB constraints are the final guard: partial unique indexes ("one active shift per driver/vehicle"), `btree_gist` exclusion constraints (assignment and settlement overlap) and unique dedupe keys. Driver-app writes carry an `Idempotency-Key`, and GPS batches, points and events carry client IDs.
- **Single revenue source:** `RevenueEntry` is the only revenue source for reports. Ride-hailing revenue comes only from an approved platform statement, and receipts are never a second revenue row. Driver cash custody goes through `DriverLedgerEntry`.
- **Exception rules** (`app/services/exception_rules.py`) are plain functions. Each returns a candidate with evidence, the thresholds used and a dedupe key. Thresholds are `EXCEPTION_*` env settings, not constants in code. Each rule runs in its own savepoint. Detection takes an advisory lock so that only one run happens at a time.
- **Reports** are `ReportDef` entries in `app/services/reports.py`. One shape serves the web table, JSON and CSV. Totals are computed from the returned rows.
- **Attachments** go through `app/core/storage.py` (local or S3-compatible). The content type is sniffed from magic bytes, and files are served only after the owning record's permission check.

## Admin web architecture

- The admin web is a **BFF**. The API token is kept in an `httpOnly` `gd_session` cookie, and all API calls happen server-side, from Server Components and Server Actions (`src/lib/api.ts`, `session.ts`, `auth.ts`). The browser never calls the API directly. `src/proxy.ts` is Next 16's replacement for `middleware.ts` and only does an optimistic redirect. A 401 from the API sends the user to `/auth/clear`.
- **Next.js 16 differs from older versions** (see `apps/admin-web/AGENTS.md`). Read the relevant guide in `apps/admin-web/node_modules/next/dist/docs/` before writing Next code. Request APIs are async, and `cacheComponents` is intentionally off. `next dev` re-adds that AGENTS.md block, so commit it rather than remove it.
- Components only present data. Pure logic lives in `src/lib/*.ts`, with a `*.test.ts` file next to it.
- **RTL:** use the logical Tailwind utilities (`ms-/me-/ps-/pe-/start-/end-`), never left or right. Use the `ltr-nums` helper for numbers, plates and codes. Numbers use Latin digits (`ar-EG-u-nu-latn`).
- **Visual style:** colours come from the tokens in `packages/config` (dark forest green primary, lime accents, white surfaces, charcoal text). Do not use a purple or blue SaaS palette, glassmorphism or decorative animation.

## Driver app

All testable logic goes in `core/` (Maven Central only): the API client, the offline sync engine, the tracking state machine and input parsing. The reason is that some development environments cannot reach Google Maven. `app/` is compiled and linted only in CI. Location is collected only during a server-confirmed shift. The debug build points at `http://10.0.2.2:8000/api/v1/`, which can be overridden with `-PgoDailyApiBaseUrl=...`.

## Product principles that constrain code

- GPS, financial, trip and alert data are never fabricated or estimated. If inputs are missing, return warnings or "insufficient data", never a guessed figure.
- Automated findings are labelled only **«مراجعة مطلوبة»** (review required) or **«حالة غير معتادة»** (unusual case). Never word anything as proven theft or fraud.
- Ride-hailing platforms are never scraped or called. Statements are entered by hand or imported from the platform's own CSV.
- There are no default accounts or passwords. The first `SUPER_ADMIN` comes from `make bootstrap-admin` with the `BOOTSTRAP_ADMIN_*` env vars.
- All configuration is in environment variables, documented in `.env.example`.
